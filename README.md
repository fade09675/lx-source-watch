# lx-source-watch

LX Music 音源可用性监测。定时在 GitHub Actions 里加载音源脚本，逐个平台取播放地址并做真实拉流校验，把结果汇总成「平台 × 可用性 × 延迟」的矩阵，托管在 Cloudflare 上。站点整站登录，面向单人或小团队自用。

> 状态：P0–P5、阶段 4A–4F、阶段 5、阶段 6A/6B/6C、界面审计收尾、A/B 任务、D、E1–E5，以及任务中心 1:1 收口（探测/补测/发现/代理/单源/订阅/清理任务化、队列操作、run 对账与重试、计划任务真实行、结构化 JSONL 日志）以及 JS 上传/下载（KV 存储、公开哈希地址、可选单源测试）已完成并上线（2026-11-28）。线上站点：<https://dash.dpdns.org>。

## 它回答什么问题

- 某个音源现在到底能不能用？酷狗、酷我、QQ、网易云、咪咕分别通不通？
- 通过几个平台、测了几个平台，失败的平台是什么原因（HTTP 4xx/5xx、非音频、超时、脚本报错）？
- 延迟多少？最近 14 天是变好还是变差？
- 哪些源值得导入 LX Music？导入链接在哪？国内网络能不能连？

## 核心设计

```
GitHub Actions                          Cloudflare
┌────────────────────────┐              ┌────────────────────────┐
│ probe job（无任何密钥）  │              │ Worker (Hono)          │
│  下载音源脚本 ≤2MB      │              │  POST /api/ingest      │
│  vm 沙箱初始化 12s      │              │   HMAC 校验 + 幂等      │
│  逐平台取链（2 首测试曲）│  ── HMAC ──▶ │  GET  /api/status ...  │
│  Range 拉流 + 魔数校验   │              │  KV  最新快照（每轮 1 写）│
│  产出 status.json       │              │  D1  历史/明细/候选/设置 │
└────────────────────────┘              └────────────────────────┘
```

- **执行不可信脚本的平面没有业务密钥**：`probe` job 不注入 INGEST_SECRET/RUNNER_TOKEN 等业务 secret，只拿一个仅能回写本任务进度的短期 `progressToken`；`persist-credentials: false`，`publish` job 只做 JSON 校验与上报，不执行音源脚本。
- **Worker 定时**：cron 每 5 分钟唤醒一次，按设置判断探测（默认 4 小时）、代理测活（默认 6 小时）、自动发现（默认 12 小时）是否到点，再派发 GitHub 工作流；手动触发时间参与判断。探测上报成功后，若开启国内补测，会再创建一个独立的「国内补测」任务；补测分两阶段：先对海外失败/未测平台用国内代理重跑取链，再对本轮全部播放地址复测，不设时间冷却，也不再塞在探测工作流里。
- **多接入点**：每个源 = 主地址 + 最多 10 个自定义镜像 + 加速模板，合计最多 16 个接入点；每轮下载全部接入点，按 sha 标记「同版本 / 版本落后」，平台测试优先主地址、其次同版本镜像。
- **所有操作进任务中心**：探测、国内补测、自动发现、代理测活、单源测试、订阅拉取、数据清理都先 `createTask` 再派发；支持排队、暂停/恢复、立即执行、取消、失败重试，探测/发现/补测/测活进度实时回写。GitHub run 对账负责把「工作流已结束但没回写」和长时间无 run 的任务收口，避免任务永远 running。
- **任务与运行日志**：每次 Actions 执行都有 task/run/log 三件套；结构化日志按行解析为 JSONL，运行详情可在「结构化 / 文本」间切换，旧 run 自动从文本日志现场转换。
- **KV 只存最新快照**，历史与明细进 D1；额度护栏默认 KV 920/1000、D1 9 万/10 万，达到阈值自动暂停派发，阈值可在设置页改。
- **状态机**：单轮失败只记为 `unavailable`，连续 3 轮全平台失败才标记「持续失效」，避免一次风控误报。
- **质量评分与推荐**：按平台通过率 50、接入点通过率 20、测试覆盖 10、26 小时内新鲜度 10、国内可达 5 计分；初始化失败扣 30 分。结果过期或国内补测全部失败会降级，避免把旧数据当成推荐源；总览默认展示「推荐 / 可用 / 全部」三档，详情页显示分数与扣分原因。
- **瞬时失败重试**：网络错误、超时、HTTP 408/429/5xx 每平台最多再试一次，间隔 600ms；4xx、非音频、空地址、脚本异常不重试，避免把确定性失败拖成慢任务。运行日志会分别记录“将重试”“重试成功”“重试仍失败”，便于回看救回率。
- **自动收录门槛**：候选自动转正前要求初始化成功、声明平台数达到门槛（默认 2），可选要求至少一个可测试平台（酷狗/酷我/QQ/网易云/咪咕/local）；门槛在设置页可调，手动收录不受限制。
- **同名多版本**：标题+作者相同但 sha256 不同的音源不再自动合并，统一列在「同名多版本」里；管理员可逐个停用，保留版本对照与回滚余地。
- **发现扩容**：发现仓库上限 200，每轮抓取默认 20（最大 120）、每仓库默认 5（最大 40），可在设置页改；Actions 侧每批 4 个仓库并发取树，保留仓库顺序、全局/单仓库上限与失败隔离。
- **GitHub 链接导入**：候选页可直接粘贴 `github.com/owner/repo`、`/tree/branch/path`、SSH 或裸 `owner/repo`，解析后预览再入库，不用手填 owner/repo/branch。
- **国内补测**：独立任务，探测完成后自动创建，分两阶段合并执行：阶段 1 对海外失败/未测平台走自备 HTTP/SOCKS 代理或 mihomo 内核节点重跑脚本取链，写「平台国内可达」；阶段 2 对本轮全部播放地址复测，写平台国内拉流结果，源接入点（主地址/镜像）另写「接入点国内可达」，不改变总状态。每轮全量复测，不设时间冷却。任务中心与探测共用 7 项摘要和完整失败明细，运行详情有独立日志；没有可补测对象时也留一条已完成任务/运行，工作台的国内补测计划项可手动「立即补测」（全量，不再限制 200 条）。
- **订阅 403 兜底**：Worker 拉订阅被 403/401 时返回结构化 `needsRunner`，前端高亮「用 Actions 拉取」，由 Actions 出口带 `RUNNER_TOKEN` 和订阅自定义 UA/headers 拉取后回传。

## 管理后台

- **导航**：监测（工作台、音源总览、音源管理、候选音源、重复与别名）、补测（国内代理、代理测活记录）、日志（运行与日志）、系统（设置、说明）；原控制面板已移除，`/admin` 重定向到设置。
- **工作台**：单列概览页，顶部渐变概览条 + 5 张指标（音源总数/平台通过/接入点通过/国内可达/候选音源）；指标下方先放额度 4 卡、轮次覆盖与快捷入口三块，再放任务中心。任务中心为「最近任务 / 操作记录 / 计划任务」三 tab：最近任务显示进度、结果摘要、失败明细、重试；队列卡支持立即执行、暂停、恢复、取消；计划任务按行显示触发、下次/上次运行、状态与立即执行，不再只是定时计划横条。国内补测计划项支持全量「立即补测」，无 200 条限制。
- **音源总览**：默认三列卡片（≤1240 两列、≤760 单列），可切回列表；每张卡显示来源、版本、状态、接入点/平台/国内/耗时、全部声明平台芯片、问题摘要、本轮主地址或镜像、复制推荐地址与详情；支持「推荐 / 可用 / 全部」质量范围、状态/平台/关键词/「只看国内失败」筛选；列表视图带质量分列，卡片对推荐源显示「推荐」标记。
- **源详情**：顶部摘要卡（状态、版本、质量分、来源、本轮入口、导入地址下拉、脚本主页）+ 5 个迷你指标；概览/平台/接入点/历史四个 tab，概览带质量等级与扣分原因；平台卡片显示取链/首字节/总耗时/拉流地址/国内补测，接入点表格显示角色、下载、版本、耗时与国内结果，长地址截断并保留完整 title。
- **音源管理**：单卡片列表，行内显示版本、中文状态、来源、接入点/镜像/最近变化；新增/编辑走右侧抽屉；备用线路导入折叠在卡片内。支持把 anhe 等第三方托管的脚本地址导入为现有音源的备用线路：按标题+作者自动匹配，或手动指定音源；预览后追加到镜像，不改变主地址。新增音源支持在线链接或直接上传 `.js` 脚本（≤2MB，按内容 sha256 去重），上传脚本生成公开哈希地址；上传时可勾选「保存后立即测试」，会创建单源测试任务。上传来源的音源行和详情页提供「下载 JS」。
- **候选源**：单卡片列表，统计卡 + 一条工具栏（搜索/仓库/状态分段），行内展示仓库路径、平台芯片、初始化/版本/首次发现与收录/拒绝；自定义仓库管理折叠在顶部，支持粘贴 GitHub 链接解析 owner/repo/branch/path。候选来自内置仓库和页面添加的仓库（每仓库/每轮有上限，可在设置页改），自动收录要求初始化通过、声明平台数达到门槛，并可选要求至少一个可测试平台；同名不同内容的相似候选仍留给人工确认。
- **国内代理**：顶部 3 张统计（节点总数/最近可用/订阅数），订阅表、批量导入、折叠的手动添加节点、节点表；导入预览/去重、独立测活与测活日志、mihomo 内核与跳板、成功率与地区。
- **运行与日志**：运行列表紧凑表格；详情分「概览 / 逐源结果 / 运行日志」三 tab，概览显示统计卡、失败原因（默认前 8 类）与步骤，逐源结果保留折叠和分页，日志单独 tab 并按 200 行分页；列表第四 tab 为「最近事件」，原控制面板的运行记录与事件已并入这里。
- **重复与别名**：统计卡 + 内容重复分组行 + 别名表；标题+作者相同但 sha256 不同的源列为「同名多版本」，可逐个停用，不自动合并；音源管理、候选、重复页的按钮与筛选统一为同一套行内链接和工具栏。
- **分页**：任务、操作记录、运行、候选、重复源、音源、代理、订阅、测活日志、运行详情源列表、运行日志、管理页事件等长列表默认每页 10 条，可切 20/50/全部。
- **移动端**：侧栏在 900px 以下收为底部 tabbar；指标卡、额度卡、候选/管理/重复行按两列或单列重排；运行记录、代理订阅/节点、后台运行记录、任务中心计划任务等表格在 760px 以下转为卡片，计划任务每行用「任务/触发/下次运行/上次运行/状态/操作」标签展示，代理节点隐藏「出口」「最近测活」次要列。
- **设置**：探测/测活/发现调度、发现扩容（每轮/每仓库上限）、国内补测（UA、代理数、并发、跳板数、自动换节点）、测活并发/超时、自动收录（最少声明平台数、可测试平台要求）、数据保留、加速镜像、清理运行记录、额度护栏与系统信息。保留天数同时驱动定时自动清理（每天最多一次）和设置页的手动预览清理；两者都永远保留最新一轮探测与测活。自动清理会作为「数据清理」任务出现在任务中心，可查看运行详情和日志；原 `/admin` 控制面板已重定向到设置页。

## 快速开始（本地）

要求 Node 22+、pnpm 11（本机 pnpm 不在 PATH 时用 `corepack pnpm`）。

```bash
pnpm install
pnpm typecheck
pnpm test
pnpm probe -- --limit 3 --prefer-mirror
pnpm validate
```

本地起 Worker + 前端：

```bash
pnpm dev:worker     # Worker，默认 8787，需要 apps/worker/.dev.vars
pnpm dev:web        # 前端开发服务器
pnpm build          # 构建前端产物到 apps/web/dist，供 wrangler 静态资源使用
```

产物在 `out/`：`status.json`（快照）、`urls.json`（本轮解析出的地址）、`candidates.json`（自动发现候选）。

### 常用命令

| 命令 | 作用 |
|---|---|
| `pnpm probe` | 探测清单内全部源 |
| `pnpm probe -- --only qingliang --deep` | 只测一个源，测更高音质 |
| `pnpm discover` | 从配置的多个 GitHub 仓库发现候选脚本（只存链接） |
| `pnpm candidates -- --limit 30` | 对候选做初始化体检 |
| `pnpm proxy-test` | 独立测活代理池 |
| `pnpm proxy-fetch -- --sub-id <id> --run-id <id>` | 由 Actions 拉取被 403 的订阅并回传 |
| `pnpm cn` | 用代理做两阶段国内补测：失败平台重跑取链 + 全部播放地址复测 |
| `pnpm cn-probe -- --probe-run-id <id> --task-id <id> --run-id <id>` | 独立国内补测任务，拉取探测输入并回传结果 |
| `pnpm ingest -- --snapshot out/status.json --dry-run` | 生成本轮上报体，不发网络 |
| `pnpm validate` | 校验清单与快照 schema |
| `pnpm db:migrate` | 本地 D1 应用迁移 |
| `pnpm audit:ui` | 真实浏览器 UI 回归：登录、桌面/移动逐页截图、404、横向溢出、控制台错误 |

`audit:ui` 复用本机已有的 Playwright Chromium、Chrome 或 Edge；需设置 `E2E_PASSWORD`，可用 `E2E_BASE_URL` 指向本地或生产站点，截图写到 `out/e2e`。

`cn`、`proxy-test`、`proxy-fetch`、`ingest` 需要运行参数：本地可传 `--proxy`/`--endpoint`/`--token`，或设 `CN_PROXY_URL`、`INGEST_URL`、`RUNNER_TOKEN`。`proxy-fetch` 还必须有对应的占位运行 `--run-id`。

## 数据与合规

- 仓库**不托管任何音频文件**，只保存音源脚本的 URL 与检测结果（是否可播放、延迟、错误原因）。
- 测试曲只用于构造 `musicUrl` 请求，不下载完整歌曲；拉流校验只读前 2KB 判断容器魔数。
- 音源脚本来自第三方仓库，本项目只做可用性事实记录，不对其内容与合法性背书。
- 如果你是版权方并认为某项内容不当，请开 issue，我们会移除对应链接。
- 自动发现只保存候选链接，不复制、不再分发第三方脚本；公开托管的 `.js` 仅限维护者主动放入 `sources/local/` 的文件。
